## Polecenie użytkownika

2026-10-24 użytkownik zatwierdził: nazwę Gnosythium; Phaser + TypeScript; osobny folder, dokumentację i lokalne repo; osobny projekt Codex i VS Code; nowy czat z Phaser + TypeScript + Vite i pierwszą areną; publiczne repo GitHub i konfigurację Pages. ## Kontynuacja

1. Przeczytaj `AGENTS.md`, `docs/CONCEPT.md`, `docs/ROADMAP.md` i ten plik w całości.
2. Sprawdź aktualny stan plików i Git. Setup repozytorium zakończono; pracujemy w zapisanym projekcie Codex bez worktree. Unikaj równoległych edycji przez inne czaty.
3. Kod etapu 1 jest przygotowany lokalnie. Przed dalszym zakresem odbierz arenę według `docs/PROTOTYPE.md`. Wyjaśniaj istotne decyzje po polsku. Nie przechodź samodzielnie do kont lub pełnego RPG.
4. Możesz sprawdzić typy i build. Nie uruchamiaj testów ani przeglądarki bez wyraźnego polecenia użytkownika.
5. Nie twórz żadnych usług backendowych i nie modyfikuj GameLogs. Konto i prawdziwe autosave'y chmurowe są wymaganiami docelowymi.
6. Nie commituj ani nie pushuj bez nowego polecenia użytkownika. „Robimy pusha” oznacza podanie komend; „zrób pusha” oznacza wykonanie. Kod musi być sprawdzony i opisany przed publikacją.

## Kontekst

Źródłowa rozmowa dotyczyła GameLogs i nauki kodu, potem przeszła w projekt gry. Użytkownik chce mieć rozdzielone projekty i pracować darmowo. Dokumenty zachowują cały istotny pomysł: mag, medieval/dark fantasy, okultyzm i magia ceremonialna, transformacja/medytacja, pięć elementów, techniczne zaklęcia (pomocniczy miecz później całkowicie wycofano), blok, pociski/AOE, zagadki i kombinacje, mroczne frakcje, tajemnicza narracja, konta/sloty/autosave/checkpointy, poziomy/skill tree i potiony, własne szkice do przyszłej grafiki.

Nie pomijaj tej wizji, ale nie próbuj realizować jej całej w jednej arenie. Propozycje asystenta nie są zatwierdzonym lore ani ostatecznym designem.
